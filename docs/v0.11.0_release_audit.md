## Authority and policy audit

The final v0.11.0 package must preserve:

- Core ownership of shared workspace, retained source, routing/dispatch,
  Academic Work Registration, Publication Records/catalogs, and module
  operations.
- ScoreForm ownership of assessment definition, generated physical identity,
  scoring, attempt assembly, native result history, producer manifests, and
  ScoreForm workflow composition.
- Meridian ownership of evidence eligibility, attempt-selection policy,
  proficiency/mastery interpretation, Grade policy, reassessment/replacement,
  aggregation, and reporting.

`scoreform.academic_result_reader` remains exact and policy-neutral. Every
attempt remains independently addressable. Blank, ambiguous, and selected
response states remain distinct.

## Compatibility boundary

Final runtime dependency:

```text
pds-core>=0.6.2,<0.7
```

Qualification layers:

- Core 0.6.2: bounded module-operations compatibility floor.
- Core 0.6.3: exact full release-qualification reference.

No ScoreForm runtime dependency/import on Meridian, Vitrine, Quillan, Concord,
Portia, or `paper-data-suite` is permitted.

The producer contract remains:

```text
module_id: scoreform
Academic Work: scoreform_academic_work_v1
publication kind: academic_result_set
manifest: scoreform_academic_result_manifest_v1
record set: academic_results
source_record: absent
capabilities: points, question_evidence, multiple_attempts
attempt behavior: preserve all; select none
```

## Downstream exact-version boundary

Paper Data Suite v0.1.0 remains an immutable released composition that
exact-qualifies its ScoreForm 0.10.0 artifact. #196 does not edit or reinterpret
that Suite release.

Meridian currently exact-binds its ScoreForm adapter to reader distribution
version 0.10.0. ScoreForm 0.11.0 preserves the underlying producer/reader
contract, but Meridian must explicitly qualify/add 0.11.0 in a Meridian-owned
change before claiming support.
