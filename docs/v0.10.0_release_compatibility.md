# ScoreForm v0.10.0 Release Compatibility Contract

Issue #170 is the release boundary for the Core 0.6 academic-publication work
implemented by #161–#169.

The release identity is:

```text
distribution: scoreform
version:      0.10.0
Core:         pds-core>=0.6,<0.7
```

The historical `v0.9.1` tag identifies an earlier Core 0.5 release and must not
be used as the downstream reader identity for the Core 0.6 publication stack.

## Producer contract frozen for v0.10.0

The release keeps these publication values exact:

```text
producer module:        scoreform
publication kind:       academic_result_set
Academic Work contract: scoreform_academic_work_v1
manifest contract:      scoreform_academic_result_manifest_v1
record set:             academic_results
source_record:           absent
capabilities:
  points
  question_evidence
  multiple_attempts
```

The Python distribution version changes to 0.10.0; these producer data-contract
identities do not change.

## Reader boundary

The released wheel contains:

```text
scoreform.academic_result_reader
```

Core-backed consumers first authorize/discover the publication and verify the
canonical manifest path and SHA-256 through Core. They then pass the already
obtained immutable bytes to the ScoreForm reader.

The reader preserves:

- every student represented by the manifest;
- every attempt independently;
- selected, blank, and ambiguous response states;
- points and correctness;
- question-to-standard alignments;
- producer provenance.

The reader does not discover publications, choose a current head, choose an
attempt, calculate a Grade, infer proficiency/mastery, or apply portfolio policy.

ScoreForm does not import or depend on Meridian.

## Vitrine non-regression

ScoreForm publishes exact academic-result evidence. It does not decide whether
that evidence belongs in a portfolio.

v0.10.0 therefore does not add:

- Vitrine Candidate objects;
- portfolio eligibility or ranking;
- showcase/improvement/graduation-path selection;
- portfolio placement or curation state;
- Vitrine Snapshot construction;
- Vitrine Subject or Portfolio identity;
- Vitrine persistence or runtime dependencies.

Standards IDs remain alignments, not portfolio eligibility. All attempts and
exact provenance remain available so future Vitrine producer discovery and
Candidate projection can be implemented additively downstream.

## Release mechanism

ScoreForm and PDS Core use verified GitHub Release wheel assets. Core 0.6.0 is
not published to PyPI, and the established ScoreForm release checklist likewise
does not publish ScoreForm to a package index.

The v0.10.0 release is complete only after:

1. the release-preparation PR passes automated qualification and the required
   source-menu rehearsal;
2. the PR is merged and the exact reconciled release commit is rebuilt and
   qualified;
3. the project owner passes the physical paper test using that exact final wheel
   and explicitly authorizes release;
4. the qualified commit is tagged `v0.10.0`;
5. the GitHub Release is created from that tag;
6. wheel/sdist assets and SHA-256 values are verified;
7. the released wheel is installed noneditably with the verified Core 0.6.0
   wheel in a fresh environment;
8. version, profile, reader, dependency, and installed producer-lifecycle checks
   pass against those assets.

Until those post-merge steps pass, this document describes the release contract,
not a claim that publication has already completed.
